Si senior full-stack vývojár, špecialista na WebAssembly, emuláciu v prehliadači, PWA aplikácie, lokálne úložisko a spracovanie veľkých súborov.

Vytvor od základu produkčne použiteľnú webovú aplikáciu s pracovným názvom:

RETROCLOUD

Ide o lokálne orientovaný online emulátor a správcu vlastných záložných kópií hier pre:

1. DOS
2. PlayStation 1
3. PlayStation 2 – experimentálny režim

Aplikácia musí fungovať na:

- Windows PC
- Linux PC
- macOS
- Android telefónoch a tabletoch
- iPhone a iPad v rámci reálnych obmedzení Safari
- moderných desktopových a mobilných prehliadačoch

Používateľ musí vedieť načítať vlastné hry:

- zo svojho zariadenia,
- zo ZIP archívu,
- z RAR archívu,
- z 7z archívu, ak použitá WASM knižnica poskytne stabilnú podporu,
- ako samostatný ISO, BIN, CUE, CHD, CSO, PBP, ELF alebo JSDOS súbor,
- cez Google Drive Picker,
- cez verejný Google Drive odkaz.

Herné súbory musia štandardne zostať iba v zariadení používateľa. ROM, ISO, BIN, CHD, BIOS ani celé archívy sa nesmú automaticky odosielať na server.

Projekt vytvor ako reálnu aplikáciu, nie ako dizajnovú ukážku alebo statický prototyp.

1. SPÔSOB PRÁCE
==================================================

Pracuj autonómne a dokonči projekt v logických etapách.

Existujúci kód považuj za nahraditeľný. Neopravuj starú architektúru iba preto, že už existuje. Projekt navrhni od jadra nanovo a existujúce súbory ponechaj iba vtedy, keď zapadajú do novej architektúry.

Najskôr:

1. skontroluj obsah repozitára,
2. vytvor súbor `plan.md`,
3. vytvor cieľovú architektúru,
4. rozdeľ implementáciu na etapy,
5. následne okamžite pokračuj implementáciou.

Nezastavuj sa po vytvorení plánu.

Nepýtaj sa po každej etape na pokračovanie.

Ak sa objaví nejasnosť, zvoľ technicky najrozumnejšie riešenie, zdokumentuj rozhodnutie a pokračuj.

Pred integráciou emulačných jadier, WebAssembly balíkov alebo externých API over aktuálnu oficiálnu dokumentáciu a licenčné podmienky.

Nikdy nevytváraj falošnú implementáciu, ktorá iba zobrazí obrazovku a nastaví stav na „running“.

Funkcia sa môže označiť ako funkčná iba vtedy, keď skutočne vykonáva požadovanú činnosť.

Ak PS2 jadro nebude možné stabilne integrovať:

- implementuj správnu modulárnu architektúru,
- PS2 skry za feature flag,
- označ ho ako nedostupné alebo experimentálne,
- nevytváraj placeholder, ktorý predstiera emuláciu.

Po každej etape spusti:

npm run typecheck
npm run lint
npm run test
npm run build

Všetky chyby oprav pred pokračovaním.

5. JEDNOTNÁ EMULAČNÁ VRSTVA
==================================================

Vytvor spoločné rozhranie pre všetky emulátory.

Použi koncept podobný tomuto:

export type EmulatorPlatform = "dos" | "ps1" | "ps2";

export type EmulatorLifecycleState =
  | "idle"
  | "initializing"
  | "loading"
  | "ready"
  | "running"
  | "paused"
  | "stopping"
  | "error"
  | "destroyed";

export interface EmulatorInputEvent {
  type:
    | "button-down"
    | "button-up"
    | "axis"
    | "key-down"
    | "key-up"
    | "pointer";
  control: string;
  value?: number;
  x?: number;
  y?: number;
}

export interface EmulatorAdapter {
  readonly platform: EmulatorPlatform;
  readonly state: EmulatorLifecycleState;

  initialize(container: HTMLElement): Promise<void>;
  loadGame(game: ImportedGame): Promise<void>;
  start(): Promise<void>;
  pause(): Promise<void>;
  resume(): Promise<void>;
  reset(): Promise<void>;

  sendInput(event: EmulatorInputEvent): void;

  saveState(slot: number): Promise<StoredSaveState>;
  loadState(slot: number): Promise<void>;
  deleteState(slot: number): Promise<void>;

  setVolume(volume: number): void;
  setMuted(muted: boolean): void;

  enterFullscreen(): Promise<void>;
  exitFullscreen(): Promise<void>;

  getPerformanceStats(): EmulatorPerformanceStats;
  destroy(): Promise<void>;

  subscribe(
    listener: (event: EmulatorEvent) => void
  ): () => void;
}

UI nesmie komunikovať priamo s js-dos, EmulatorJS alebo Play!.js.

Všetky emulátory musia byť ovládané cez adapter.

Adapter musí emitovať reálne udalosti:

- initialized
- game-loading
- game-ready
- started
- paused
- resumed
- state-saved
- state-loaded
- error
- destroyed
- performance-update

Stav „running“ nastav až po potvrdení, že emulačné jadro skutočne beží.

PS2 implementuj cez aktuálny browserový build Play!.js, ak je reálne a licenčne možné ho integrovať.

PS2 musí byť označené:

EXPERIMENTÁLNE

Použi feature flag:

NEXT_PUBLIC_ENABLE_PS2=false

Predvolená hodnota má byť `false`, kým nebude Play!.js reálne integrovaný a otestovaný.

PS2 nesmie byť označené ako funkčné iba preto, že sa zobrazí canvas.

Reálne PS2 minimum:

- inicializácia Play!.js WASM jadra,
- načítanie podporovaného obrazu,
- vykresľovanie hry,
- zvuk,
- vstupy,
- pause,
- resume,
- reset,
- správne ukončenie.

Podporované formáty zobraz iba po reálnom overení.

Možné formáty:

- ISO
- CHD
- CSO
- ELF

Ak jadro daný formát nepodporuje, nezobrazuj ho ako podporovaný.

Pred spustením zobraz:

- stav WebAssembly,
- WebGL2,
- dostupnú pamäť, ak ju možno odhadnúť,
- počet CPU jadier,
- výkonový profil,
- upozornenie na experimentálnu kompatibilitu.

Pridaj výkonové profily:

- výkon
- vyvážené
- kvalita

Ak Play!.js nemožno integrovať, PS2 stránka musí korektne uviesť:

„PS2 emulačné jadro zatiaľ nie je v tomto zostavení dostupné.“

Nevytváraj falošné tlačidlá save state alebo reset.

10. ZIP, RAR A 7Z
==================================================

ZIP:

- použi fflate alebo inú vhodnú knižnicu,
- nepoužívaj `unzipSync()` na hlavnom vlákne,
- spracovanie vykonaj vo Web Workeri,
- používaj streaming alebo postupné spracovanie, kde je to možné.

- použi libarchive.js alebo inú stabilnú WebAssembly knižnicu,
- WebAssembly assety hostuj lokálne,
- rozbaľovanie vykonaj vo Web Workeri,
- over podporu RAR4 a RAR5,
- ošetri archívy chránené heslom,
- ak formát nie je podporovaný, zobraz presnú chybu.

Pred úplným rozbalením skontroluj:

- počet súborov,
- deklarovanú veľkosť,
- kompresný pomer,
- hĺbku priečinkov,
- vnorené archívy,
- dostupné miesto.

Nikdy nerozbaľ celý potenciálne nebezpečný archív ešte pred bezpečnostnou validáciou.

12. VEĽKÉ SÚBORY A OPFS
==================================================

Nečítaj niekoľkogigabajtové súbory pomocou:

file.arrayBuffer()

Nevytváraj pre celé ISO alebo CHD jeden obrovský ArrayBuffer.

Veľké súbory:

- zapisuj do OPFS po častiach,
- používaj streamy,
- zobrazuj priebeh,
- umožni zrušenie,
- kontroluj dostupné miesto počas zápisu.

Použi:

navigator.storage.estimate()
navigator.storage.persist()

Pred importom zobraz:

- veľkosť súboru,
- dostupné miesto,
- odhad potrebného miesta.

Ak úložisko nestačí, import nezačni.

Vytvor bezpečné OPFS utility:

- normalizePath
- ensureDirectory
- writeStream
- readSlice
- deleteRecursive
- calculateDirectorySize
- listDirectory
- cleanupPartialImport

Pri neúspešnom importe vykonaj rollback všetkých čiastočne uložených súborov.

20. GOOGLE DRIVE
==================================================

Implementuj dva režimy.

A. Google Drive Picker

Použi:

- Google Identity Services
- Google Picker API
- Google Drive API

Použi najmenší potrebný scope, ideálne:

https://www.googleapis.com/auth/drive.file

Aplikácia nesmie automaticky prehľadávať celý Drive.

Používateľ musí vybrať konkrétny súbor.

Zachovaj:

- názov,
- MIME typ,
- veľkosť,
- file ID,
- pôvodnú príponu.

B. Verejný Google Drive odkaz

Podpor:

- /file/d/FILE_ID/view
- /open?id=FILE_ID
- /uc?id=FILE_ID
- export=download&id=FILE_ID

Parser musí:

- validovať URL,
- overiť doménu,
- bezpečne extrahovať ID,
- odmietnuť neplatný vstup.

Pred stiahnutím zisti metadata, ak sú dostupné.

Veľké súbory:

- neposielaj cez Vercel API,
- neukladaj celé do RAM,
- streamuj priamo do OPFS, ak to CORS dovolí.

Ak priame stiahnutie blokuje CORS alebo Google confirmation stránka:

- nezobraz falošnú chybu,
- ponúkni Google Picker,
- prípadne vysvetli, že používateľ musí súbor stiahnuť manuálne.

Environment variables:

NEXT_PUBLIC_GOOGLE_CLIENT_ID=
NEXT_PUBLIC_GOOGLE_API_KEY=
NEXT_PUBLIC_GOOGLE_APP_ID=

OAuth token neukladaj do localStorage.
